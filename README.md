# DuoPlan

Приложение для пар: общие планы, значимые даты, общий дневник и вишлисты.

## Архитектура

| Путь | Назначение |
|---|---|
| `worker.js` | Production backend: API, Telegram webhook, авторизация initData |
| `migrations/` | Схема Cloudflare D1 |
| `public/` | Лендинг, Mini App и страница активации |
| `duoplan/` | Локальный/legacy Python-бот (aiogram + SQLite) |
| `tests/` | pytest-тесты Python-части |

**Production:** Cloudflare Worker + D1 + Telegram Mini App.  
**Python-бот:** отдельная локальная поверхность. Он не должен работать одновременно
с Worker на одном `BOT_TOKEN`: webhook и long polling конфликтуют (`409`). При
старте Python-бот проверяет `getWebhookInfo` и отказывается запускать polling,
если webhook уже установлен.

Схема общих таблиц задаётся только миграциями D1 и `ensureSchema` в `worker.js`;
`duoplan/db/schema.py` обязан совпадать с ними по составу колонок (расхождение
ловит `tests/test_schema_parity.py`). Ритуал дня считается одной и той же
функцией на обеих поверхностях — `dailyAction()` в `worker.js` и
`_daily_action()` в `duoplan/services.py`; паритет держат
`tests/test_daily_parity.*` на общих векторах из `tests/fixtures/daily_actions.json`.

Публичный адрес: `https://duoplan.stacheight.workers.dev`.

## Cloudflare

В `wrangler.jsonc` уже указаны Worker, D1 binding, assets и production origin.

Секреты Worker:

| Имя | Назначение |
|---|---|
| `BOT_TOKEN` | Токен @BotFather |
| `WEBHOOK_SECRET` | Случайная строка для проверки Telegram webhook |
| `SETUP_TOKEN` | Необязательный отдельный секрет для `/api/setup` |

Активация:

1. Задайте секреты в **Workers & Pages → duoplan → Settings → Variables and Secrets**.
2. Откройте `/setup` (или `/setup.html`), введите `SETUP_TOKEN` либо `BOT_TOKEN`.
3. Страница создаст/обновит таблицы D1, установит webhook и кнопку Mini App.

### Кэш статики Mini App

`/app.js` и `/app.css` отдаются через Cloudflare Workers assets; в `public/_headers`
им выставлен `Cache-Control: public, max-age=300`. Чтобы деплой не оставлял
пользователей на старом скрипте (API мог бы разойтись), пути версионируются
query-string: `/app.css?v=<APP_VERSION>` и `/app.js?v=<APP_VERSION>` (сейчас
`2026.10.30.2`). Новый деплой → новый URL → новый cache entry; HTML при этом
no-cache, поэтому свежая версия подхватывается сразу без ожидания TTL.

### Telegram: кнопка «ОТКРЫТЬ» в списке чатов (Main Mini App)

Синяя кнопка «ОТКРЫТЬ» рядом с чатом бота в списке чатов — это **Main Mini App**.
Кодом она не ставится, только вручную в @BotFather:

1. `/mybots` → выбрать бота → **Bot Settings → Configure Mini App → Main Mini App**.
2. Указать `https://duoplan.stacheight.workers.dev/app` (совпадает с `APP_ORIGIN` в `wrangler.jsonc`).
3. По желанию загрузить иконку и скриншоты — они покажутся в профиле бота.

Проверка: `POST /api/setup` отдаёт `has_main_web_app: true` (из `getMe`), а в
списке чатов у бота появляется кнопка «ОТКРЫТЬ». Меню-кнопка у поля ввода
(`setChatMenuButton` с web_app) ставится кодом на шаге 3 «Активации».

Полный экран и кнопка «на главный экран» — клиентские API Bot API 8.0+
(`requestFullscreen`, `addToHomeScreen`), фронтенд вызывает их сам; на старых
клиентах и Telegram Desktop приложение просто остаётся в оконном режиме.

### Напоминания в боте (cron)

`wrangler.jsonc` задаёт 15-минутный cron (`triggers.crons`): `sendDigests()` в
`worker.js` раз в четверть часа обходит пары и отправляет каждому партнёру
личные сообщения от бота с кнопкой Mini App.

- **Утренняя сводка** — планы и значимые даты на сегодня и завтра, двумя
  абзацами («Значимые даты» / «Планы»). Время настраивается на вкладке
  «Наша пара» → «Настройки» (персональное, по умолчанию 09:00, можно выключить).
- **Сводка о датах за сутки** — завтрашние даты накануне в выбранное время
  (отдельная настройка, тоже персональная и отключаемая).
- **Напоминания о планах** — если у плана указано время, бот предупреждает
  за 3 часа и за 1 час (всегда включены, дедуп по `task3h:<id>`/`task1h:<id>`).
- Дедупликация — таблица `notification_log` (ключ `tg_id, day, kind`), хвост
  старше недели чистится на каждом тике; сбой доставки (кроме постоянных
  ошибок вроде заблокированного бота) повторится на следующем тике.
- Личные даты (`dates.is_private=1`) попадают в сводки только их автору
  (`created_by`), из выдачи партнёру они убираются ещё в SQL `state()/archive`.
- Личные планы (`tasks.is_private=1`) — зеркально датам: партнёр не видит их
  ни в списках, ни в напоминаниях; по прямому `id` API отвечает 404, чтобы не
  раскрывать факт существования записи. Автору заголовок приходит под
  спойлером «Скрытый» (`<tg-spoiler>`), чтобы план-сюрприз не читался с экрана
  блокировки. Списки в самом боте (`DuoPlanService.tasks/dates` с `viewer_id`)
  фильтруют чужие личные записи так же.
- Часовой пояс — `pairs.timezone`; бюджет подзапросов Free-плана (50/вызов)
  ограничивает число пар за тик, остальные догоняют на следующих тиках.
- Там же в «Настройках» выбирается акцентный цвет интерфейса (персональный,
  хранится в `users.accent_color`, палитры в `public/app.js`).

### Выход из пространства

- Пока партнёр не присоединился (`pairs.user_b=0`), на вкладке «Наша пара»
  показывается карточка «Приглашение партнёра» с кодом и ссылкой. После входа
  партнёра (`user_b` заполнен) карточка скрывается; `state()` при этом не
  отдаёт код, чтобы им нельзя было поделиться из готовой пары.
- Если партнёр выходит (`POST /api/pair/leave`), сервер обнуляет `user_b`
  (а когда уходит владелец — передаёт пространство партнёру и делает его
  владельцем). У оставшегося карточка приглашения появляется снова: `state()`
  возвращает прежний код пары, и по нему можно позвать партнёра ещё раз.
- Оставшийся партнёр получает сообщение от бота: «<имя> больше не в вашем
  пространстве» с кнопкой Mini App. Выход фиксируется в БД до отправки, поэтому
  сбой Telegram не отменяет само действие.

### Ссылка у желания

- У желания есть опциональная ссылка (`wishes.url`), которую пользователь
  указывает при создании («что именно он хочет» — подарок, билет и т.п.).
- В карточке желания ссылка не выводится текстом: вместо неё кнопка «Ссылка»,
  при тапе пользователь открывает указанную ссылку. Кнопка есть и у исполненных
  желаний — у готового желания ссылка сохраняется.
- При редактировании карточки ссылка подставляется в поле ввода и сохраняется
  через `PATCH /api/wishes/:id`.

### Разметка текста (Telegram-стиль)

Заголовки планов и дат, воспоминания и желания хранят разметку прямо в тексте
теми же маркерами, что и Telegram: `**жирный**`, `_курсив_`, `__подчёркнутый__`,
`~~зачёркнутый~~`, `||спойлер||`, строки с префиксом `> ` — цитата.

- В Mini App при выделении текста в поле появляется плавающее меню
  (жирный/курсив/подчёркнутый/зачёркнутый/спойлер/цитата); повторное нажатие
  снимает маркер. Рендер — `renderRichText()` в `public/app.js`: текст
  экранируется до наклейки тегов из фиксированного набора, произвольный HTML
  из поля не проходит. Спойлер раскрывается тапом, цитата красится в
  акцентный цвет пользователя (`--berry*`).
- В уведомлениях бота ту же разметку разворачивает `richToHtml()` в
  `worker.js` (HTML-поднабор Telegram: `<b>`, `<i>`, `<u>`, `<s>`,
  `<tg-spoiler>`, `<blockquote>`); незакрытые маркеры закрываются
  автоматически, чтобы `sendMessage` не вернул 400.
- Списки в самом боте (aiogram) рендерит порт `richToHtml` —
  `duoplan/richtext.py`: `rich_to_html()` собирает HTML, `rich_to_plain()`
  снимает разметку для подписей inline-кнопок (кнопки `parse_mode` не
  поддерживают). `safe_edit(..., html=True)` передаёт `parse_mode="HTML"`
  только этим сообщениям, остальные тексты остаются plain-текстом, поэтому
  «<» в служебных сообщениях и ошибках ничего не ломает.
- Каждый пункт списка рендерится отдельным блоком (`handlers.rich_list_item`):
  номер, дата и автор приписываются снаружи, а разметка заголовка — внутри,
  поэтому цитата с первой строки становится `<blockquote>`, а не текстом «> ».

### Нижняя навигация (Liquid Glass)

Панель и «жидкая» капля живут в `public/nav.js` (фабрика `createLiquidNav`),
разметка — в `public/app.html`, материал — в `public/app.css`, связь с
остальным приложением — в `public/app.js` (`updateDroplet` → `setActive`).

- **Материал.** Полупрозрачный фон `--nav-glass-bg`, размытие и насыщение
  (`backdrop-filter: blur(34px) saturate(175%)`), верхний блик `--glass-sheen`,
  внутренняя окантовка `::after` (`--glass-inner`), мягкая тень. Значения
  свои для светлой и тёмной темы.
- **Капля.** Это SVG-путь, а не `scaleX/scaleY`: контур пересчитывается по
  скорости и направлению — передний край вытягивается (до 18% ширины), задний
  поджимается (11%), высота проседает (16%), центр смещается на 5%. У края
  панели форма сдвигается внутрь, а не сплющивается. Градиент капли — от
  `--droplet-hi` через `--droplet-fill` к `--droplet-deep`, тень —
  `--droplet-halo`; все они пересчитываются в `applyAccent()` из палитры.
- **Жест.** Захват начинается на активной вкладке (капля лежит под ней),
  порог 6 px отделяет тап от перетаскивания. Дальше `setPointerCapture` на
  панели: `pointermove` приходит даже когда палец вышел за её пределы, а
  вертикаль игнорируется — капля едет только по горизонтальной дорожке.
  `pointercancel`, `lostpointercapture` и `blur` откатывают жест без
  переключения; синтетический `click` после drag гасится один раз.
- **Выбор вкладки.** При отпускании контур капли сэмплируется
  (`getPointAtLength` + `getScreenCTM`), пересечение с каждой вкладкой
  считается клиппингом полигона (Sutherland–Hodgman) и площадью по формуле
  шнурков. Знаменатель — **полная площадь капли** (`coverageRatios`), а не
  сумма пересечений: иначе часть капли, лежащая вне кнопок, завышала бы долю
  до 100%. Нужно строго больше 50% с допуском 0.2% против численной
  погрешности; при 50/50 или «размазано» остаётся последняя однозначная цель.
  Пока палец не отпущен, страница не переключается — только подсветка
  `.is-preview-target`. Во время жеста с вкладок снят `:active`-масштаб,
  иначе `getBoundingClientRect()` возвращал бы сжатые прямоугольники.
- **Защита от двойного click.** После успешного drag запоминается одноразовая
  запись `{pointerId, x, y, time}`; capture-обработчик гасит только click,
  совпавший по указателю, координатам (±14 px) и времени (700 мс). Отмена
  жеста (`pointercancel`, `lostpointercapture`) защиту не ставит, клавиатурные
  клики (`detail === 0`) не подавляются, а новый `pointerdown` сбрасывает
  запись.
- **Проверка.** `tests/test_nav_geometry.test.mjs` — геометрия и правило 50%;
  `tests/nav-harness.html` — интерактивный прогон в браузере (тапы, drag,
  выход за панель и за экран, отмена, подавление click). Harness открывается
  как обычная страница; в headless Chrome кадры подменяются таймером.

### Масштаб интерфейса

Pinch-to-zoom в Mini App отключён на трёх уровнях, чтобы не зависеть от
поведения конкретного WebView:

- **viewport** в `public/app.html`: `maximum-scale=1, user-scalable=no`
  (плюс прежние `width=device-width`, `initial-scale=1`, `viewport-fit=cover`);
- **CSS**: `html { touch-action: pan-x pan-y }` — прокрутка одним пальцем
  разрешена в обе стороны, pinch-zoom и double-tap-zoom выключены. Панель
  навигации сохраняет свой `touch-action: pan-y`, поэтому горизонтальный drag
  капли не страдает;
- **`public/zoom-guard.js`**: отменяет `touchstart`/`touchmove` при двух и
  более касаниях (одиночные не трогает), Safari-события `gesturestart`,
  `gesturechange`, `gestureend` и `Ctrl+wheel`; все слушатели с
  `{ passive: false }`.

`index.html`, `setup.html` и `404.html` — самостоятельные страницы вне
Telegram WebView, там масштабирование оставлено (доступность).

Проверка: `tests/test_zoom_guard.test.mjs` (обработчики, viewport, CSS) и
`tests/zoom-harness.html` (реальные TouchEvent, computed styles, drag капли
при включённой защите).

### Фон при прокрутке

Длинный свайп на iOS давал полосы другого цвета у верхней и нижней границы:
при отскоке (rubber-band) обнажается фон **WebView**, а туда уходил ключ
`bg_color` — цвет темы Telegram (в тёмной теме чёрный), а не фон приложения
`#161514`.

- `applyTheme()` теперь читает `--bg` через `themeBackground()` и передаёт
  фактический hex в `tg.setBackgroundColor()` и `tg.setHeaderColor()`; тем же
  значением обновляется `<meta name="theme-color">`. Ключ `bg_color` остался
  только запасным вариантом, если `--bg` не hex.
- `html`/`body` красятся `var(--bg)` и получают `overscroll-behavior-y: none`;
  `body` имеет `min-height: 100dvh`, поэтому при коротком содержимом под ним не
  остаётся незакрашенной области. Обычная прокрутка, sticky-шапка и нижняя
  навигация не затронуты.

Проверка: `tests/test_scroll_theme.test.mjs`.

### Календарь на вкладке «Наша пара»

Карточка календаря стоит между участниками пространства и настройками
(`renderPairCalendar()` в `public/app.js`). Сетка месяца с понедельника, точки
событий и раскрывающийся список выбранного дня.

- **Данные.** Планы — `mergedArchive("tasks", appState.tasks)` (только открытые,
  только с заполненным `day`); значимые даты — `mergedArchive("dates", …)`;
  вручённые желания — `mergedArchive("done_wishes", appState.completedWishes)`.
  Завершённые планы и планы без даты в календарь не попадают.
- **Маркеры.** Зелёный — план, красный — значимая дата (`--cal-task`,
  `--cal-date`), жёлтая звезда — вручённое желание (`--cal-wish`), серый —
  личная запись (`--cal-private`). По одному маркеру на тип, цвета
  семантические и не зависят от акцентной палитры. Обе темы задают свои оттенки.
- **Вручённые желания.** Звезда ставится в день, когда желание отметили
  исполненным (`wishes.done_at`, миграция `0010`). Показываются только свои:
  `owner_id` сверяется с `appState.user.tg_id`, чужие подарки в календарь не
  попадают. У записей, закрытых до появления колонки, даты вручения нет —
  звезды у них не будет.
- **Ежегодные даты.** `recurs` проецирует запись на тот же месяц и день в
  каждом году, начиная с года создания; 29 февраля показывается только в
  високосные годы (проверка через `calendarDaysInMonth`, без переноса даты).
- **Приватность.** Календарь не делает собственных запросов: он использует
  `state` и `/api/archive`, где фильтр `(is_private=0 OR created_by=?)` стоит
  в SQL. Личные записи партнёра в календарь не попадают.
- **Догрузка.** `/api/state` отдаёт до 200 активных записей (и 10 последних
  вручённых желаний); если лимит достигнут, `ensureCalendarArchive()` в фоне
  листает `/api/archive` до `hasMore: false`, дедуп по `id`, без блокировки
  первого рендера.
- **Навигация.** Месяц и выбранный день живут в модуле (`calendarMonth`,
  `calendarSelected`), поэтому обычный refresh не сбрасывает их. Смена месяца
  снимает выделение; клик по дню соседнего месяца перелистывает календарь.

Проверка: `tests/test_calendar.test.mjs` (сетка, границы года, 29 февраля,
ежегодные и обычные даты, сортировка событий, расположение карточки).

Локальная проверка Worker:

Примечание: не запускайте `wrangler d1 migrations apply` на базе, уже инициализированной через `/setup` — схема в production управляется Worker'ом.

```bash
wrangler d1 migrations apply duoplan --local
wrangler dev --local --port 8788
```

Для локального dev создайте `.dev.vars` (он в `.gitignore`) с тестовыми
`BOT_TOKEN`, `WEBHOOK_SECRET`, `SETUP_TOKEN`, `APP_ORIGIN`.

Перенос локальных данных в production D1:

```bash
.venv/Scripts/python.exe scripts/export_sqlite_to_d1.py
wrangler d1 execute duoplan --remote --file data/duoplan-d1-import.sql
```

Перед импортом сделайте резервную копию D1: скрипт использует `INSERT OR REPLACE`.

Импорт предназначен для пустой или подготовленной целевой D1: при совпадении ID существующие записи могут быть заменены каскадно. Для объединения с работающей базой сначала проверьте конфликты ID.

## Python-бот

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
cp .env.example .env          # заполните BOT_TOKEN
.venv/Scripts/python.exe -m duoplan
```

Переменные: `BOT_TOKEN`, `DB_PATH`, `TZ`, `BOT_NAME`, `FSM_TTL`
(см. `.env.example`). Секреты хранятся только в `.env`, он в `.gitignore`.

База по умолчанию — `data/duoplan.db`. Версия схемы хранится в
`PRAGMA user_version`, миграции идемпотентны и не удаляют существующие данные.
FSM-состояния хранятся в SQLite с TTL.

## Проверки

```bash
.venv/Scripts/python.exe -m pytest
node --test "tests/*.test.mjs"
node --check worker.js
node --check public/app.js
wrangler deploy --dry-run
```

Тесты покрывают гонку входа в пару, запрет входа владельцу пустой пары, двойное
начисление XP, валидацию, часовой пояс, FSM-медиа и миграции.

## Версия

Версия Python-пакета задаётся в `duoplan/__init__.py`; `pyproject.toml` читает её
через `dynamic = ["version"]`. Версия Worker — `APP_VERSION` в `worker.js`.
