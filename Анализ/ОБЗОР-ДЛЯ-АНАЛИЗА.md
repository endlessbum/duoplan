# Обзор проекта «Общий дневник» (duoplan) — для анализа

Telegram Mini App для пар: общие планы, значимые даты, дневник, цитаты, желания, места, кино, копилки. Плюс legacy-бот на Python (уведомления/диалоги).

## Стек и деплой

- **Backend**: Cloudflare Worker — `worker.js` (единый файл, ~2800 строк): REST API `/api/*`, Telegram webhook `/telegram/webhook`, cron `*/15` (уведомления), схема БД.
- **БД**: Cloudflare D1 (SQLite) — миграции в `migrations/`, схема также поднимается `ensureSchema` в воркере.
- **Frontend**: vanilla JS SPA в `public/` — `app.js` (~4300 строк), `app.css`, `nav.js` (нижняя навигация с «каплей»), `zoom-guard.js`. Без фреймворков, рендер строками.
- **Legacy-бот**: `duoplan/` (Python, aiogram) — оставшиеся сценарии: уведомления, экспорт, FSM-диалоги.
- **Конфиг**: `wrangler.jsonc` (worker «duoplan», D1 «duoplan», cron, `OWNER_IDS` — приватный гейт).
- **Версионирование**: `APP_VERSION` == `DB_SCHEMA_VERSION` (тест следит за равенством); ассеты `public/app.*` версируются `?v=` в `app.html`, хеши — `tests/asset-hashes.json`.

## Секреты (в копию НЕ включены — осознанно)

- `.env` (реальный BOT_TOKEN), `.dev.vars` (локальные заглушки + OMDB_API_KEY/TMDB_API_KEY).
- Секреты Cloudflare: `OMDB_API_KEY` (карточка фильма: рейтинг/жанр/длительность), `TMDB_API_KEY` (русские названия/жанры).
- `.env.example` — шаблон с плейсхолдерами.

## Карта ключевых файлов

| Файл | Что внутри |
|---|---|
| `worker.js` | Весь API: авторизация (HMAC initData, окно 7д), `state()`, CRUD планы/даты/дневник/цитаты/желания/места/кино/копилки, экспорт `/api/data/export` (TXT), cron-уведомления, `ensureSchema` |
| `public/app.js` | Весь клиент: рендер вкладок (home/tasks(Планы\|Кино)/dates/places/memories + пара: Профиль\|Желания\|Копилка), диалоги, refreshState с автообновлением |
| `public/app.css` | Дизайн-система: карточки, пилюли (.day-chip/.stat-pill), .card-action, сегменты, тёмная/светлая темы |
| `migrations/` | Пронумерованные D1-миграции (0001–0019) |
| `tests/` | Node-тесты (extractBraced-подход: функции извлекаются из worker.js/app.js без запуска сервера) + pytest |
| `scripts/` | `export_sqlite_to_d1.py` (перенос legacy-SQLite → D1), `backup-d1.sh` |
| `duoplan/` | Legacy Python-бот (handlers, fsm, db/schema.py) |

## Как запускать тесты

```bash
node --test tests/*.test.mjs   # 427 тестов
python -m pytest tests/ -q     # 142 теста
```

Локальный стенд для визуальной проверки UI: вне репозитория (Telegram-заглушки + мок `/api/state`), фронтенд тестируется через node-тесты и стенд.

## Известные инварианты (легко сломать при правках)

1. `APP_VERSION` == `DB_SCHEMA_VERSION` (тест `test_webhook_hardening`).
2. HMAC-валидация initData: поле `signature` НЕ исключается из data-check-string (исключается только `hash`).
3. `/api/gender` — выше membership-гейта в `api()` (онбординг до создания пары).
4. `state()` и `archivePage()` сортируют один и тот же полный набор без SQL LIMIT (пагинация только в архиве).
5. Приватность: `is_private=1 AND created_by=user` фильтруется в SQL (state, archive, экспорт) — личные записи партнёра не должны попадать в выдачу ни в каком составе.
6. Специфичность CSS: `.card p {color:var(--muted)}` перебивает одно-классовые селекторы для `<p>` внутри карточек — новые тексты в `.card` требуют минимум `.card .class`.
7. Тесты извлекают функции из worker.js/app.js через `extractBraced` (баланс фигурок) — сигнатуры с деструктуризацией `{a, b}` в параметрах ломают извлечение.
8. Кеш-бастинг ассетов: при изменении `public/*` — обновить `?v=` в `app.html` и `tests/asset-hashes.json`.
